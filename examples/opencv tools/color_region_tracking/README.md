# Color-distribution region tracking

Open `mean_shift.json` or `cam_shift.json`, then select **Run all**. The first
image teaches one green target; the remaining seven return a center pose,
tracked region, confidence, native geometry and probability image. Reset the
sequence memory before replaying the example from its first image.

- `mean_shift.json` follows a translated rectangle with a fixed-size window.
- `cam_shift.json` follows a growing, rotated ellipse. Edit the connected
  **Editable teaching region** to change the initial target selection.
- `loss_and_expiry.json` deliberately removes the target on frames 8–10.
  These frames fail and withhold primary outputs. Frame 11 contains the target
  again but remains expired until an explicit reset or rising `reseed` input.
  Its installed CLI run intentionally exits with a failure result.

Inspect the tracker's **Results** tab or open a result image. Graphics are object
overlays; the output image preserves its source pixels and color encoding.
Debug draws current accepted geometry and a status label. Lean omits graphics.
Filename tickets and coordinate payloads follow each current frame. The tracker
uses serial sequence memory; independent stream IDs have separate models.

## Teaching and controls

**Track region by color** is under **OpenCV → Video analysis → Object tracking**.
Supply an initial `[x,y,width,height]` parameter or connect a rectangle, circle,
polygon or another image-space region to `seed`. The seed is read only when
teaching. An optional work mask and region intersect to restrict eligible pixels
both when teaching and when calculating probability. Dark, desaturated and
optionally bright or transparent pixels are excluded by explicit controls.

Choose hue or joint hue/saturation histograms, bin counts, termination flags,
iteration count and convergence epsilon. The histogram is peak-normalized to
255, including a uniform single-color target. `learning_rate=0` freezes it;
nonzero values blend only accepted updates. Expose `histogram` to export the
model and its original training ticket; it is hidden and unserialized by default.

Confidence is mean backprojection divided by 255 inside the native search box;
it is not a calibrated probability of correct tracking. Support fraction counts
box pixels above `support_threshold`. Quality controls also limit area relative
to the original seed and optional motion from the last accepted center. Rejected
updates retain the previous model/window. After `max_misses` consecutive misses,
the model expires; a continuously connected seed does not silently retrain it.

Initialization always waits for a subsequent update, even with warmup set to one.
`ready` and `status` remain available while image/pose/geometry events are withheld.
Use `reset` or a rising `reseed` to explicitly teach again. Changing recipe,
coordinate grid or algorithm parameters resets that sequence context by default.

## Geometry and limits

Inputs are uint8 BGR, RGB, BGRA, RGBA or explicitly tagged native HSV (H 0–179),
limited to 2.1 million pixels and 16,384 per axis. Alpha can exclude teaching
and tracking pixels; the source image's stored alpha is preserved. Grayscale
and higher depths need an explicit color/depth conversion upstream.

MeanShift emits a zero-angle center pose. CamShift can emit a principal-axis
pose; its angle has 180-degree ambiguity and is withheld for near-circular
distributions. Both the ellipse and its area describe **color mass**, not
physical part dimensions. A similarly colored distractor, occlusion or abrupt
motion can invalidate this single-target model; it does not establish identity.
See [OpenCV's tracking API](https://docs.opencv.org/4.x/dc/d6b/group__video__track.html)
for the underlying MeanShift/CamShift algorithms.

## Fixture and validation

All 20 PNG images and project graphs are original MIT-licensed synthetic tool
fixtures, generated by `build_example.py`. No customer or third-party images are
included. Each graph also contains an attribution/scope comment.

`truth.json` defines target positions independently of the tracker. Tests require
centers within 3 pixels, at least 1.4× CamShift area growth, correct disappearance
and expiry, native histogram/window parity, ticket preservation, and Debug/Lean
execution. These controlled fixtures demonstrate the tool contract; they are not
a qualification of tracking reliability on captured production images.
