# Metric depth encoding

Open [the project](metric_depth_encoding.json) and run it once. The fixture is
a Float32 TIFF with six known depth bands. **Quantize metric depth to uint16**
encodes them at 1/1024 meter per code, reserves 65535 for invalid samples, and
clamps positive depths beyond the representable range. **Decode and scale
metric depth** uses the scale carried by the graph connection and emits
Float64 millimeters with NaN for invalid depth.

| Band | Input depth | Expected uint16 code |
| --- | --- | --- |
| Missing | 0 | 65535 |
| Below range | One quarter of a code | 1 |
| In range | 1024.25 codes | 1024 |
| Midpoint | 1536.5 codes | 1536 |
| Midpoint | 1537.5 codes | 1538 |
| Above range | 70 m | 65534 |

The example clamps 1,536 samples and decodes 3,840 valid depths. Its in-range
maximum absolute error is 0.48828125 mm, exactly half a code. The retained
error includes clamped measurements and is larger. Change **Out of range**
to **Invalidate** to emit invalid codes for those same 1,536 samples. Set the
decoder's scale and invalid-code parameters when loading untagged raw codes
from an image file. [OpenCV depth conversion reference](https://docs.opencv.org/5.0/main_modules/ptcloud_rgbd.html#rescaledepth)

The synthetic fixture was generated by the project contributors and is
covered by the repository's MIT license. Use `build_example.py --output <empty-folder>`
to regenerate the saved graph and depth TIFF.

```powershell
opencv-dataflow-run "examples/opencv tools/metric_depth_encoding/metric_depth_encoding.json" --profile lean
```
