# Recover planar camera motion

Open `planar_camera_motion.json` and run once. The graph finds SIFT
correspondences on a synthetic textured plane seen by two calibrated
pinhole cameras. **Image-only alternatives** reports two valid motions.
**Resolve motion with known plane** uses the measured source normal and a
1.45 m perpendicular distance to select one metric pose.

The example uses 366 matches. The selected pose has 0.0955 px RMS on
ideal target pixels. Translation differs from the known pose by **0.131 mm**,
and rotation differs by **0.0047°**. Equivalent plane fits can have
nearly identical pixel evidence, so the block exposes all surviving
hypotheses and flags ambiguity.

Wire a query/train match record or paired source and target coordinates.
The source and target camera models supply each view's intrinsics,
distortion and distinct optical frame. Both point sets must use their
calibrated image grids. Attach the images to see fit inliers and outliers
as result graphics. For versioned camera models the attached images also
provide capture revision evidence.

The transform maps source camera coordinates into target camera
coordinates. The block uses the calibrated homography convention
`H = R + (t/d) nᵀ`, where `n` points from the source camera toward the
plane and `d` is the perpendicular distance. It filters native visibility
candidates and checks positive depth in both views.

The optional **Source plane** accepts a fitted metric depth-plane or
cloud-plane record in the source camera frame. Alternatively, configure
the normal and distance using the block parameters. A known distance
scales every surviving translation. The **Pose** output requires one
surviving metric solution. Multiple surviving motions remain in
**Hypotheses**. Rotation-only fits emit a rotation hypothesis.

The pattern, images and geometric truth were generated by
OpenCVDataflowGUI contributors under the project's MIT license. Run
`build_example.py --output <empty directory>` to recreate them.
