# Sparse depth backprojection

Open [the project](sparse_depth_backprojection.json) and run it once. The
**Backproject depth pixels** block uses a synthetic depth step and the
matching undistorted camera intrinsics. Inspect the point cloud and the report
to see which requests produced metric camera XYZ.

The example uses a 1.0 m near plane and a 1.6 m far plane. Five of seven
requests produce points, including a repeated request. A missing depth and
an out-of-frame coordinate are reported separately.

| Requested XY | Sampled XY | Expected XYZ in meters |
| --- | --- | --- |
| (25, 14) | (25, 14) | (−0.15, −0.175, 1.0) |
| (55, 14) | (55, 14) | (0.24, −0.28, 1.6) |
| (24.6, 41.2) | (25, 41) | (−0.15, 0.1625, 1.0) |
| (57, 40) | (57, 40) | Missing depth |
| (0, 55) | (0, 55) | (−0.4, 0.3375, 1.0) |
| (80, 14) | Outside frame | Outside frame |
| (25, 14) | (25, 14) | (−0.15, −0.175, 1.0) |

The native binding reads sparse depth at the selected pixel coordinates.
This block checks bounds and invalid values before calling it, applies the
configured physical units, and records the original request and sample
indices. Use pixels on the same grid as the depth image. For lenses with
distortion, use a depth image and camera model already rectified for
backprojection. [OpenCV point cloud documentation](https://docs.opencv.org/5.0/main_modules/ptcloud_rgbd.html#depthto3dsparse)

The synthetic image was generated by OpenCVDataflowGUI contributors and is
licensed with the project under MIT. Run `build_example.py --output <empty-folder>`
to rebuild the project and image.

```powershell
opencv-dataflow-run "examples/opencv tools/sparse_depth_backprojection/sparse_depth_backprojection.json" --profile lean
```
