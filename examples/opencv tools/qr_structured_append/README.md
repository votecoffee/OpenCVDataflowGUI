# Structured-append QR recovery

Open a project with **File → Open**. Use **Run** for a scene, or **Run all** for
the three-file batch. Inspect the reader's Text, Complete, Status and Fragments.
Failed sets deliberately emit no Text/Bytes hex event; their status explains why.
No camera, plugin, optional barcode package or download is required.

| Project | Expected outcome |
| --- | --- |
| [Shuffled scene](shuffled_scene.json) | Pass: physical order 2,0,1 recovers the exact full payload. |
| [Shuffled image batch](shuffled_group.json) | Pass after Run all: files 2,0,1 are batched; each fragment keeps its filename ticket/grid. |
| [Missing part](missing.json) | Fail: missing index 1. |
| [Duplicate part](duplicate.json) | Fail: a complete set plus a repeated index 1 is not a valid set. |
| [Foreign fragment](mismatched.json) | Fail: incompatible native parity/header identity. |
| [Inconsistent count](mixed_count.json) | Fail: fragments declare different set sizes. |
| [Parity collision](collision_digest.json) | Fail: a foreign payload shares the eight-bit parity; the expected full-payload SHA256 detects it. |
| [Damaged raw modules](damaged_header.json) | Fail: native OpenCV can repair the payload, but conservative header verification requires intact raw format/codewords. |

The intended payload is `PART-0042/LOT-A-INSPECTION-1234567890`. Each project pins
its SHA256 and expects three fragments. Order comes from the symbol's actual
header; filenames, graph order and generator payload metadata are not used as
identity. Without a known digest, QR parity cannot distinguish every mixed set.

Single-image result graphics label each part and show its outline/axes in the
original camera grid. Passing graphics are green, aggregate failures amber.
Image groups keep geometry and ticket/grid metadata per member instead of
pretending the acquisitions share a camera frame. The separate Batch block
handles serial acquisition; this reader has no partial state across runs.

From the repository root:

```powershell
opencv-dataflow-api run "examples/opencv tools/qr_structured_append/shuffled_scene.json" --summary
opencv-dataflow-api run "examples/opencv tools/qr_structured_append/shuffled_group.json" --all-images --summary
```

All fixture images, payloads, placement references and projects are original
OpenCVDataflowGUI contributor work under MIT. They are generated by
`build_example.py` using native OpenCV QRCodeEncoder, without customer/third-party
images. Every project contains an attribution/comment block. The application's
two QR block-layout tables derive from Project Nayuki's MIT QR generator; their
full notice and pinned source are included in `qr_rs_tables.py`.

Regenerate with `python "examples/opencv tools/qr_structured_append/build_example.py"`.
`truth.json` pins source image bytes, known camera placements and expected payload.
See [the contracts](../../../docs/qr-structured-append.md) for native controls,
codeword integrity, text decoding, budgets, error behavior and explicit limits.
