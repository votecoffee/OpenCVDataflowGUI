# Inspect a camera projection matrix

Open `projection_matrix.json` and run once. **Recover and verify** takes
a known camera projection stored at a negative scale. It recovers the
camera model and both pose directions. **Project with recovered geometry**
then projects eight known points into the example image.

| Quantity | Expected result |
| --- | --- |
| Camera center in the fixture | (2.4, −1.6, 0.83) m |
| Focal lengths | 1120 px horizontal, 1040 px vertical |
| Principal point | (371.2, 270.1) px |
| Field of view | 39.29° horizontal, 32.16° vertical |
| Focal lengths with the 12.8 × 9.6 mm active sensor | 17.92 mm horizontal, 16.64 mm vertical |
| Reprojection RMS across the eight synthetic points | Below 2 × 10⁻¹² px on the tested runtime |

Supply the full 3 × 4 matrix in the block configuration or connect its
**Projection** input. Declare the ideal image width and height, world
frame, camera frame and world coordinate units. Supply both active sensor
dimensions in millimeters for physical focal lengths, pitch and principal
point. Image dimensions and physical aperture come from the supplied
configuration. A projective matrix by itself has no physical scale label.

**World to camera** maps points into optical axes. **Camera to world**
places the camera in the world, with the camera center as its translation.
The report retains complete intrinsics, including skew. A reusable pinhole
camera model is emitted for zero-skew geometry. It describes ideal rays
with zero distortion.

Optional matched object and image points check reprojection in the supplied
frames. An attached ideal image shows the principal point and point checks
as result graphics. Rank-deficient or ill-conditioned matrices fail without
geometry. A point-check failure retains the decomposition for diagnosis.

The image and numerical truth were generated by OpenCVDataflowGUI
contributors under the project's MIT license. Run
`build_example.py --output <empty directory>` to recreate the example.
