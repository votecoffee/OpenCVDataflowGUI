# Estimate motion blur and restore with a qualified PSF

Open a project with **File → Open…**, then Run. Select Estimate linear motion
blur under **Custom → Image processing → Restoration**. Its Report shows the
fit/validation tiles, conditional candidate, score gap and acceptance reason.
Accepted PSFs feed Wiener deblur. The filmstrip shows restored output on success
or the annotated degraded image when no PSF is accepted.

| Project | Expected result | Demonstrates |
| --- | --- | --- |
| [horizontal.json](horizontal.json) | Pass | Recover an eight-pixel horizontal path. |
| [diagonal.json](diagonal.json) | Pass | Recover a twelve-pixel path at 35°. |
| [vertical.json](vertical.json) | Pass | Recover a sixteen-pixel vertical path. |
| [mild_noise.json](mild_noise.json) | Pass | The twelve-pixel diagonal path with two-code-unit Gaussian noise. |
| [highdepth.json](highdepth.json) | Pass | BGR uint16 estimation and restoration preserve values above 255. |
| [masked.json](masked.json) | Pass | One region controls eligible estimation tiles and restored output pixels. |
| [ambiguous.json](ambiguous.json) | Fail; no restoration | A nine-pixel path between coarse even-length candidates lacks the required distinct-hypothesis margin. |
| [flat.json](flat.json) | Fail; no restoration | Constant data has no useful contrast. |
| [sharp.json](sharp.json) | Fail; no restoration | An unblurred texture lacks evidence for the searched blur family. |
| [heavy_noise.json](heavy_noise.json) | Fail; no restoration | Twenty-code-unit noise overwhelms the motion signature. |
| [validation_mismatch.json](validation_mismatch.json) | Fail; no restoration | Fit tiles contain horizontal motion and validation tiles vertical motion. |

Debug and Lean have identical numerical judgments. Lean omits optional graphics
and Diagnostic. Rejected estimates withhold PSF/Length/Angle; the connected PSF
input prevents Wiener deblur from falling back to a configured default kernel.

## Controlled data and limitations

The source is a seeded **512×512** approximately isotropic noise texture with
mean 110 and standard deviation 25. Blur is independently generated by
**257-point trapezoidal integration** of a bilinear pixel-space line path with
circular boundaries. The generator does not import the production PSF helper,
run the estimator or derive expected parameters from an estimated result.
The uint16 sharp image stores values multiplied by **257, 180 and 120** in BGR
channels before independent degradation. Source files are fixed PNGs; the
disconnected Sharp truth block is never an estimator input.

Tests require accepted lengths within **one pixel**, directions within **five
degrees modulo 180°**, and restored MSE below **80%** of degraded-image MSE
against the separate clean reference. The masked case also verifies unchanged
pixels outside the selected left half. These are fixture-specific bounds.
[truth.json](truth.json) records known parameters, case controls and source hashes.

The model assumes one centered, uniform linear-motion PSF over approximately
isotropic texture. Radial whitening helps remove the texture's isotropic spectral
envelope; it cannot distinguish arbitrary anisotropic scene content from blur.
Fit and validation use different whole image tiles. Their textures can still be
correlated, and successful validation is not a guarantee of a physical camera
trajectory. The model floor is not measured SNR; tune Wiener regularization
separately. No arbitrary, defocus or spatially varying kernel is recovered.
See the [full contracts](../../../docs/blur-estimation.md).

Run or regenerate from the repository environment:

```powershell
python -m opencv_dataflow.assistant_cli run "examples/custom tools/motion_blur_estimation/diagonal.json" --profile debug --summary
python "examples/custom tools/motion_blur_estimation/build_example.py"
```
